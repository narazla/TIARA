# 02 — MVP Scope

## MVP Philosophy

The MVP must be **real and functional** — not a static mockup. It must demonstrate a working end-to-end flow: from elderly check-in to caregiver dashboard analytics. Every major component must have real logic, even if simplified.

---

## MVP Features (In Scope)

### 1. Real Authentication
- Register and login with hashed passwords (bcrypt)
- JWT access tokens
- `/auth/me` endpoint
- Protected routes on both frontend and backend
- Role assignment at registration

### 2. Role-Based Access Control
- `elderly`, `caregiver`, `healthcare` roles
- Redirects based on role after login
- Caregiver routes additionally protected by PIN
- Middleware-based route protection on backend

### 3. Elderly Home Page
- Personalized welcome message
- Daily check-in status indicator
- Quick access to Daily Check-In and TIARA Companion
- Profile dropdown with Dashboard and Logout

### 4. Video + Audio Daily Check-In
- Browser `getUserMedia` for camera + microphone access
- Live video preview during check-in
- `MediaRecorder` for audio/video capture per question
- Consent-based: permissions requested before recording starts

### 5. Spoken AI Questions (Text-to-Speech)
- `SpeechSynthesisUtterance` Web Speech API
- Questions spoken aloud by TIARA
- Text question panel shown simultaneously
- Visual status indicator (speaking / listening / processing)

### 6. Audio Recording and Upload
- Per-question audio recording
- Collected and uploaded to backend on check-in completion
- Metadata stored in `media_files` table

### 7. Speech-to-Text Transcription Pipeline
- **Primary**: `faster-whisper` or `whisper` Python library
- **Fallback**: Clean provider interface with manual placeholder — not static fake data
- Transcripts stored in `transcripts` table
- Pipeline runs asynchronously after upload

### 8. Voice Feature Extraction
- Audio duration
- Approximate speech rate (words per minute if transcript available)
- Hesitation markers (um, uh, "I forgot", etc.)
- Repetition count
- Pause indicators
- Voice risk score composite

### 9. Facial / Video Signal Analysis
- Save video file metadata (duration, format)
- Basic face detection attempt using OpenCV or MediaPipe if available
- Service interface structured for real implementation
- Graceful fallback with clear TODO markers if library unavailable

### 10. Daily Check-In Result for Elderly
- Simple, warm result page
- No risk score, no clinical detail
- "You're doing great" encouragement
- Link back to home

### 11. PIN-Protected Caregiver Dashboard Access
- `/caregiver/pin` route
- PIN hashed in database (bcrypt)
- Backend verification endpoint
- Session flag after successful verification
- Wrong PIN error message

### 12. Caregiver Analytics Dashboard
- Risk score trend chart (Recharts)
- Memory consistency indicator
- Response delay indicator
- Speech hesitation indicator
- Patient profile summary
- Latest check-in card

### 13. Alerts System
- Alerts generated by `AlertService` after each check-in
- Triggers: missed check-in, declining memory score, rising risk level
- Severity levels: info, warning, critical
- Displayed on Alerts page

### 14. Care Recommendations
- Generated by `RecommendationService` based on risk level and indicators
- Sections: cognitive activities, social interaction, routine maintenance, when to seek help
- Editable caregiver notes

### 15. Dementia Guidance AI
- Working chatbot at `/caregiver/guidance`
- Backend `/guidance/ask` endpoint
- Rule-based fallback if no LLM API key configured
- LLM provider abstraction (pluggable)
- Always shows medical disclaimer

### 16. Reports Page
- Monthly summary report generated from stored sessions
- Print-friendly layout
- PDF generation via backend library if available (WeasyPrint or ReportLab)
- Download PDF button

### 17. Healthcare Worker Basic Dashboard
- Patient list with risk filter
- Latest session summary per patient
- Longitudinal trend view
- Report access

### 18. Secure and Clean Project Structure
- Monorepo: `frontend/`, `backend/`, `docs/`
- Environment variables via `.env` and `.env.example`
- Docker-ready: `Dockerfile` per service, `docker-compose.yml`
- Alembic migrations
- Seed script for demo users
- README with full setup instructions

## Post-MVP Features (Out of Scope for Competition)

| Feature | Notes |
|---|---|
| Advanced facial expression model | Requires custom ML training |
| Emotion recognition | Needs labeled dataset |
| Custom trained cognitive decline model | Beyond rule-based scoring |
| RAG with validated medical knowledge base | Requires curated corpus |
| PDF report generation (advanced) | Basic version in MVP |
| Push notifications | Mobile infrastructure |
| WhatsApp / email caregiver alerts | Third-party integration |
| Clinical portal enhancement | FHIR, EHR integration |
| Admin dashboard | User management, analytics |
| Multi-patient caregiver support | Pagination, filters |
| Offline mode | PWA, local storage sync |
| Audio/video encryption at rest | Key management infrastructure |
| Automated longitudinal model training | MLOps pipeline |

---

## MVP Success Criteria

The MVP is considered complete when the following end-to-end flow works without manual intervention:

```
1. Elderly user logs in → routed to /elderly/home
2. Clicks "Daily Check-In"
3. Camera + microphone granted → video preview shown
4. TIARA speaks and displays first question
5. User records answer → clicks Next Question
6. All questions answered → clicks Finish Check-In
7. Media uploaded to backend
8. AI pipeline runs: transcription → voice analysis → language analysis → risk scoring
9. Alerts and recommendations generated
10. Elderly routed to /elderly/check-in/result (warm result only)
11. Caregiver navigates to /caregiver/pin → enters 123456
12. Routed to /caregiver/dashboard → sees updated analytics from real session data
13. Alerts page shows generated alerts
14. Recommendations page shows care plan
15. Guidance AI responds to caregiver questions
16. Reports page shows monthly summary
```
